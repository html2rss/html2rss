# Context

Contributor map for request, AutoSource, and selectors seams.

## Native feed preference

Same-origin RSS/Atom/RDF preference for curation gates (Capture defer/`--force`, Recon `:defer`).
Owned only by `Syndication::Discovery.best_feed_url` (head alternates + path probes via session).
`PageRecon` may still expose `alternate_feeds` for Inspect diagnostics — that list is not a second preference algorithm.

## Scrape target

Immutable entry vs effective fetch URL for one pipeline run. Owned by `Html2rss::ScrapeTarget` — constructed from `Config#url`, sticky-updated only when `FeedResolution.try_apply!` returns `:succeeded` (retry extract yielded items). Tournament wins with an empty retry leave `effective_url` on the entry URL so later auto-fallback strategies do not inherit a failed rewrite. `RequestSession.build` accepts an optional `scrape_url:` override. `Config` stays unchanged.

## Page assessment

Cheap surface class and admitted article count for probe scoring. Owned by `PageRecon::Assessment` via `PageRecon.assess` (fixed AutoSource limit). Empty-extract error labels use `PageRecon.surface_category_for` (classify only — no second AutoSource). Full pipeline extract counts stay on `FeedPipeline#deduplicated_articles`; tournament policy uses that typed `articles:` array.

Diagnostic URL fetch for curation inspect and recon is owned by `PageRecon::Diagnostics` (via `PageRecon.probe` → `PageRecon::Probe`: `session`, `response`, `result`, `strategy`).

## Syndication candidate catalog

Shared path lexicon for native feed discovery and entry-resolution listing guesses. Owned by `Syndication::CandidateCatalog` (`FEED_PATHS`, `LISTING_PATHS`). `Syndication::Discovery` and `FeedResolution::CandidateGenerator` consume it.

## URL document identity

Trailing-slash and fragment-insensitive same-document compare. Owned by `Html2rss::Url#same_document?`. `FeedResolution::CandidateGenerator` filters with it. Differs from `Url#==` (slash-sensitive).

## URL article identity

Scheme-, fragment-, trailing-slash-, query-param-order-, and tracking-param-insensitive "same article" key (closed `Url::TRACKING_PARAM` set: `utm_*`, `fbclid`, `gclid`, `msclkid`, `mc_cid`, `mc_eid`, `ref`, `ref_src`; every other query param stays significant). Owned by `Html2rss::Url#article_identity`; `AutoSource::PageLinks` keys rendered anchors by it and `Cleanup` dedupes, rejects self-links, and audits URL diversity by it, so one rule decides all. A kept corroborated item whose URL differs from its content anchor only by these takes the anchor's URL minus tracking params (`Url#without_tracking_params`), never downgraded from `https` to `http`, so the item guid stays stable (`PageLinks#canonical_url`, applied by `Cleanup`).

## Feed resolution policy

Whether the entry URL tournament runs. Owned by `FeedResolution::Policy` — requires typed `articles:` Array (`ArgumentError` otherwise; derive count from `articles.size`), surface weak/blocked predicates, and NativeFeed ≥50% majority (`scraper == AutoSource::Scraper::NativeFeed`).

## Feed resolution candidates

Same-origin probe URL mix for the tournament. Owned by `FeedResolution::CandidateGenerator`: one Discovery feed slot + up to `max - 1` listing URLs (taxonomy-first nav → segment first-wins `:list` → `:cluster` → `:semantic` → `LISTING_PATHS`). Listing seeds stay in that mix; a concatenated list truncated with `.first(max)` drops them.

## Feed resolution scoring

Probe score weights, drop penalties, and winner pick for the entry URL tournament. Owned by `FeedResolution::Scorer`. `FeedResolution::Probe` fetches via `PageRecon.assess` (not fat `PageRecon.call`).

## Surface category

Closed surface class for no-scraper / assessment gates. Owned by `Html2rss::SurfaceCategory` (`weak?` / `blocked?` / `listing_bonus?`). `PageRecon::Assessment` exposes those predicates; `FeedResolution::Policy` and `Scorer` call them.

## Entry-resolution options

Typed `auto_source.entry_resolution` expansion. Owned by `FeedResolution::Options` (`enabled?`, `max_probes`, `request_slots`). Policy eligibility, Runner probe caps, and budget slot reservation consume it.

## Pipeline outcome URLs

`FeedPipeline::PipelineOutcome` carries `ScrapeTarget` plus optional `FeedResolution::Diag`. `Status.build` maps to wire `entry_url` / `scrape_url` / `entry_resolution` Hash. `Diag.applied: true` means the tournament picked a winner; it does not mean wire `scrape_url` changed. Only `Status` `scrape_url` / `ScrapeTarget.effective_url` reflect a sticky rewrite after a successful retry.

## Request Budget

Shared wall-clock and HTTP request meters for one feed build. Constructed via `RequestSession::RuntimePolicy.resources_for(config)` (policy + budget from one expansion); `budget_for` remains a thin alias. `FeedPipeline` builds sessions with `RequestSession.build` (Context normalizes once). `RequestService::Context` requires an explicit `budget:`. Adapter attempt timeouts resolve through `Budget#effective_timeout_seconds` / `#effective_timeout_ms`. Auto fallback run state lives on `FeedPipeline::AutoFallback::AttemptState`. Article collection threads `FeedPipeline::ExtractionContext`.

## HTML-ness

`RequestService.response_cache=` is an opt-in seam for initial fetches (`RequestService::ResponseCache`: TTL, bounded, 2xx only; key is a digest incl. `Policy#cache_key`). Only the MCP process installs it (default 300s, `HTML2RSS_RESPONSE_CACHE_TTL`; `0`/`off` disables); hits surface as `Response#cache_age` and the envelope `cache` field (MCP contract v4). The seam lives in `RequestService::ResponseCaching`; the cache is also bounded to 32 entries / 32 MiB.

Whether a response document is HTML is owned by `RequestService::Response#html_response?` (Content-Type `text/html`, or a non-JSON body matching `Response::HTML_BODY_SNIFF`). `content_type` stays the wire header. Capture, Channel, and curation inspect all call that one predicate. Gzip/brotli inflate stays on `CompressedBody`, called only from the HTTPX adapter.

## Botasaurus scrape contract

OpenAPI 2.0 `ScrapeRequest` / `ScrapeSuccess` / `ScrapeError` is the wire authority. CI locks client constants against `spec/fixtures/botasaurus/openapi.yaml` (vendored sibling snapshot); when `../botasaurus-scrape-api/openapi.yaml` is present locally, specs assert the fixture still matches. Closed sets, wait bounds, request option keys, and `window_size` `{width, height}` live on `RequestService::BotasaurusContract`. `Config::Validator::BotasaurusRequestConfig` consumes those constants for YAML admission (`scroll` is scroll-to-bottom). `BotasaurusStrategy` is HTTPX `POST /scrape` plus gem error mapping: 200 → `Success`; 4xx/5xx → `Error` (`challenge_block` → `BlockedSurfaceDetected`, `timeout` / 504 → `RequestTimedOut`, otherwise `BotasaurusServiceError`). **Transport hop** (HTTP to scrape-api, not JSON body): `User-Agent` = `RequestHeaders::DEFAULT_USER_AGENT`, `Accept-Encoding: identity`, per-execute `X-Request-Id`. Target headers stay in `ScrapeRequest.headers`. scrape-api honors inbound `X-Request-Id` for all `diagnostics.request_id` envelopes. `Response#transport_meta` is `diagnostics` plus success-only `metadata_error`.

## DOM chrome

Layout noise and primary-link recognition for the **manual selector** path: ignored container tags/paths, class-clustering exclusions, utility landmarks, heading tags, main-anchor CSS, and visible-text extraction. Owned by `Html2rss::Html::Navigator` (+ `TextExtractor`); its tag sets and skip-href prefixes derive from `SST::Tags`, the single vocabulary owner. `Html::ArticleExtractor` serves selectors only.

Heuristic auto-source chrome lives on `SST::Tags` / `SST::Text` after `SST::Normalizer` (sole Nokogiri on that path). Visible text (`SST::Text`, and its Nokogiri port `Navigator::TextExtractor`, one rule) separates block children by a newline and other neighbours by a space, except that an inline element embedded in direct text (text on both sides) and touching it without whitespace stays in its word (`Straßenbah<span>n</span> für` → `Straßenbahn für`); adjacent elements and an element opening or closing its parent's text (`<span>Live</span>Headline`) always separate, since sites lay those out as blocks with CSS. `SST::Index#ignored_chrome?` is set by the Normalizer through the one rule `Tags.chrome_scope`: stripped tags (and `noscript`, kept only for its file links, § Media enclosures) and the ARIA roles `navigation`, `menu`, `menubar`, `dialog` and `alertdialog` are chrome anywhere (`search` is not: a search landmark may wrap the result list); `header`/`footer`/`nav` and the roles `banner`/`contentinfo` are chrome only at page level, not under `Tags::SECTIONING_NAMES` (`article`/`section`/`aside`/`main`), matching ARIA banner/contentinfo scoping, so card permalinks in `<article><header>` and a news list in `<main><nav>` stay content. A pager stays chrome in any scope. A `nav` is a pager when its `aria-label` names pagination, a class-token part does (`gsc-pagination`, not `paginated-list`), or it links `rel=next`/`prev`. A `ul`/`ol` is a pager only when its `aria-label` names pagination or a whole class token is `pagination`/`pager`/`paging` (not `js-pagination-container` or `infinite-pager`), and at least half its links look like page navigation (`rel=next`/`prev`, a `?page=`-style query or `/page/N` path, or a page number, arrow or prev/next text), since feed lists are often named after their infinite-scroll pager. Pagination labels are nouns (`Pagination`, `paginación`, `pager`, `page navigation`), never `paginated`. Chrome is inherited: a header under a page-level `nav` or footer stays chrome. `dialog` is chrome like role=dialog, and role=main opens sectioning content like `main`. The same rule owns the peripheral scope: a utility landmark that is not chrome (`Tags.utility_landmark?`: `nav`/`aside`/`footer`/`menu`, or a navigation, menu, dialog or complementary role) opens a sticky `:peripheral` scope, read through `SST::Index#peripheral?`; `aside` stays peripheral rather than chrome or content (sidebars hold real but secondary links). `SST::Node#utility_landmark?` asks the same predicate. `Navigator.usable_card_parent?` applies the same scoping to card walks: utility landmarks by tag or role are never a card, and header/footer or banner/contentinfo roles stop the walk only at page level (SST nodes read `ignored_chrome?`; Nokogiri nodes fold `Tags.chrome_scope`). A card kicker is passed to `Article` apart from the headline: `Html::TitlePieces` excludes date, time and concealed elements and noise pieces of the kicker (`Article::Title.noise_piece?`: clock, field label such as `Section:`, type marker); see § Article title.

## Visibility

Which elements a sighted reader does not see. Owned by `Html2rss::Html::Visibility` (plain attribute inputs, so SST and Nokogiri callers share it), in two kinds: **unrendered** (`hidden` attribute, inline `display:none`, utility classes `hidden` / `d-none` / `is-hidden` / `hide`) and **screen-reader-only** (`SCREEN_READER_CLASS`: `sr-only`, `visually-hidden`, `h-offscreen`, `_screen-reader-only`, `screen-reader-text`, `off-screen`, `element-invisible`, with utility/BEM prefixes and a `-focusable` variant). `aria-hidden="true"` is neither (seen, not spoken). Sponsorship labels count while spoken (`unrendered?` only); titles and item anchors keep only what is seen (`concealed?`, either kind).

## Default items selector

The wire spelling is owned by `Html2rss::Selectors::DEFAULT_ITEMS_SELECTOR`. The runtime CSS that spelling expands to is owned by `Html::Navigator::MAIN_ANCHOR_SELECTOR`. `Config.prepare_defaults` merges the default only when `selectors:` is present. Auto-source-only configs stay selector-free. An explicit selector, including `a` or `.card`, is not rewritten.

## Container assessment

Observing a semantic container plus its selected anchor and destination facts into ranking signals. Owned by `Html2rss::Scoring::Engine` (+ `ContainerAssessor`). `LinkResolver` owns token regexp derivation from `PathClassifier::SEGMENT_SETS` (`CONTENT_TOKEN_REGEXP` / `JUNK_TOKEN_REGEXP`); ContainerAssessor consumes those defaults (or injected regexps). Rank-time hard drops live on `Scoring::Observation#hard_junk?` (container assessment — not content-anchor eligibility). `SemanticHtml` / `Html` orchestrate Normalizer → Segmenter → Scoring → `Html::SstArticleExtractor` only. Scrapers supply one page-scoped `Scoring::LinkResolver` into Segmenter, Engine, and SemanticHtml dedup.

## Content-anchor eligibility

Whether an anchor is junk chrome vs a content permalink. Owned by `Html2rss::LinkDestination::NoisePolicy`. An anchor a sighted reader does not see (`Html::Visibility.concealed?` on the anchor itself: unrendered or screen-reader-only, such as the off-screen accessibility twin of a teaser link) is noise. Utility-landmark ancestry is computed by `AutoSource::Segmenter#landmark_ancestor?` and injected as `utility_landmark_ancestor:` — NoisePolicy does not walk `SST::Index`. Primary-link ranking weights are inlined in `Segmenter::PrimaryLink#candidate_facts`. Feature ids and `Score`/`RankedSegment` factories live on `Scoring::Engine`. Segmenter discovers candidates and may _call_ NoisePolicy; it does not own eligibility weights. Scrapers pass the page `LinkResolver` into Segmenter so DestinationFacts memoization stays local to the page run.

## Feed-item admission

Whether an extracted candidate may become a feed item. Owned by `Html2rss::AutoSource::Cleanup` (scheme/domain/self-link/title floor, destination-class hard exclude, sponsored items, **and** the structured-tier page check). Destination facts come from `LinkDestination::DestinationFacts` / `PathClassifier` — Cleanup does not own path lexicon Sets. Title string backstop stays `Cleanup.junk_reason` only. Scoring may demote or rank-time drop for heuristic discovery; it does not admit feed items. `AutoSource` short-circuits Html when earlier tiers already admitted ≥1 clean article below `limit` (quality over padding). Tier stop counts Cleanup-admitted items only, so items the page check drops never stop later tiers; of those, structured items the page does not show in its content (`Corroboration#shown?`) never count either, nor do media items (`Article#media?`) except on a media page (`Corroboration#media_page?`: more than half of the page-read items shown in its content are media, each article identity once, judged only after a heuristic tier read the cards; there media count and come first: media items, then the other counting items, each group in the document order of its content anchors, `Corroboration#page_order` over `PageLinks#content_position`), and the final `limit` cap takes counting items first. A native feed's items come first and pass the same admission rules (sponsorship included); Cleanup's dedupe is the one merge owner: the first copy of an article identity keeps its fields and later copies fill only the ones it lacks (`Article#merge`).

## Structured-tier corroboration

Whether an in-page structured item is backed by the rendered page. Which scrapers are checked: `AutoSource::Scraper::CORROBORATED_SCRAPERS` (Schema, Microdata, Microformats2, JsonState, XhrArticles, JsonDocument); native feed, CMS REST API, sitemap, and oEmbed items are publisher-declared and exempt. Where a URL is rendered: `AutoSource::PageLinks` (one pass over SST anchors keyed by `Url#article_identity`; `:content`, `:peripheral` from `SST::Index#peripheral?` (aside, menu, role=complementary, in-content nav, sectioned footer), `:chrome` from `SST::Index#ignored_chrome?`, else `:absent`; `#sparse?` for no page, a degraded SST, or at most two content URLs). The keep/drop verdict and its private article-likeness score (dates, image, description, URL shape, scraper-cohort size and parent-path cohesion): `AutoSource::Corroboration#verdict`. Content placement keeps; chrome-only and unrendered URLs drop (`chrome_only`, `not_on_page`) unless the page is sparse; peripheral and sparse-page items keep on score, else drop as `unlikely`. Absence drops only when the page renders the item's scraper cohort (at least half of it as content anchors, or fewer than three items); a cohort the page mostly does not render (app shell with consent or legal links, aggregator redirect anchors) is scored with absence counting one against it. A shallow path ending in a post slug is a root-level permalink, not a section root. Cleanup runs the check before dedupe and tallies the reasons, so a dropped structured copy leaves its URL to a heuristic tier and a kept one wins dedupe. `AutoSource` memoizes the SST and page `LinkResolver` lazily: the first consumer (page check or heuristic tier) builds them, at most once per page. JsonState keeps no chrome rules of its own.

## Sponsored items

Whether an item is explicitly sponsored. Marker vocabulary owned by `Html2rss::LinkDestination::Sponsorship.marker`, in three kinds. **Container** markers state that an element is paid content: a `rel` token `sponsored`, a `data-sponsored` / `data-advertorial` value from the closed truthy set (`true`, `1`, `yes`; an empty value, bare attribute, `no`, `null`, `false`, `0` or `off` is off), a sponsored or advertorial class token (whole, BEM `card--sponsored`, `is-sponsored`, `sponsored-content`; never `unsponsored`, nor `has-sponsored`, which marks a wrapper that contains one), a native-advertising class token (`NATIVE_AD_CLASS`: a whole `native`, a BEM `teaser--native` / `card__native`, or a `native-ad` / `adv-native` / `ad-native` block with suffix words such as `adv-native-strip`; never `native-input`, `nativeApp`, `native-teaser` or a blockless `--native`), or an ARIA label that is an ad label. **Label** markers (`:label`) are an ad-label class token (`ad-label`, `ad-badge__item`) or a standalone element whose whole text is an ad word (`LABEL_PATTERN` group `ad`: "Ad", "Advertisement", "Anzeige", "Werbung", "Publicité", "Publicidad", "Pubblicità", "Advertentie", "Reclame", "Reklama", "Annons", "Reklam", "広告", "スポンサー", "Promoted", which also names a team or a person moving up; "PR" only as a whole uppercase element text, `ELEMENT_LABEL`, never ARIA). **Paid labels** (`:paid_label`) are a standalone element whose whole text states paid content (group `paid`: "Sponsored", "Paid content", "Partner content", "Advertorial", "Gesponsert", "Contenu sponsorisé", "Contenus partenaires", "Publireportage", "Contenido patrocinado", "Contenuto sponsorizzato", "Informazione pubblicitaria", "Gesponsord", "Sponsorowane", "Materiał partnera" / "partnerski" / "promocyjny" and plurals, "Sponsrat innehåll", "Annonssamarbete", "タイアップ", "スポンサーリンク", "広告企画", "PR企画"); paid attribution ("Sponsored by …", "Gesponsert von …", "Sponsorisé par …", "Patrocinado por …", "Contenuto sponsorizzato a cura di …", "Gesponsord door …") may name the sponsor in up to five words. Both text sets are one closed list (en, de, fr, es, it, nl, pl, sv, ja). Attribution that states no payment ("Presented by", "Präsentiert von", "In Kooperation mit", "En partenariat avec", "proposé par", "In collaborazione con", "In samenwerking met", "I samarbete med", and the Japanese "提供" / "提供：…", which also credits wire and content partners) is no label, nor is the editorial word "Partners" / "Partenaires". An ad word also names the advertising trade, so it counts only on a plain element; a paid phrase also counts on a heading or a topic chip (category, tag, kicker class). A class or text label counts only on a rendered element: neither it nor an ancestor inside its card (`Sponsorship::CARD_NAMES`) is unrendered (`Html::Visibility.unrendered?`: a `hidden` attribute, `display:none` or hiding utility class `hidden` / `d-none` / `is-hidden` / `hide`; a hidden tab panel or responsive wrapper around whole cards hides none of their labels); `aria-hidden="true"` (a visual label) and screen-reader-only classes (a spoken label) still count. A class marker also needs content. A text label never counts inside running text: not as anchor text, not inside a heading, not in an inline element of prose (or of an inline topic chip, for an ad word), and not when the element holds other text (a meta line). Item titles and URL paths are never read. `SST::Normalizer` keeps `rel`, `hidden`, `data-*` and `aria-*` in `Attrs#raw` for it.

`AutoSource::PageLinks::SponsoredCards` scopes each marker in one walk. A container holding anchors marks every destination inside it. A marker inside an anchor (a **linked label**, such as a kicker link or a teaser link holding "Annons") marks that anchor's destination across its card unit: the largest unit around the anchor that is still one card (`Html::CardWalk.crowded?`: one destination, at most one heading), and only when that unit holds a heading, so a footer link `<a><span>Werbung</span></a>` binds nothing. Any other label (or anchorless container) marks the card it sits in: its nearest `article`, `section`, `aside` or `li` (the marked element itself included; `main` is a page region, never a card). That card marks its dominant destination: its only destination, else its only headline destination (an anchor in or around a heading), so secondary image, tag or sponsor links do not hide the card while a card with several headlines marks nothing. A paid label outside every anchor binds at its first ancestor holding a destination after it (none before it) and climbs no further: when that ancestor is one card unit holding a heading, the label marks that card when it sits in it alone (a bare `div` card included); when the label is the frame's header (below) and the frame holds no heading outside its card units (the largest one-card subtrees holding a destination, rooted outside a heading), the label **heads a section** and every destination in it is marked. A section label is the section's **header** (`PageLinks::LabelBinding`): it sits in the frame's first child holding words, and it or a wrapper of it there is a heading, a `header` element or a header box (class word `header`, `head` or `heading`); the header may also hold a sponsor logo, a name or an info button. A label in plain text before the cards — an ad caption over an empty, `ins` or stripped `iframe` slot, or a bare label over a strip of cards — heads nothing (an accepted miss for an unmarked bare label). Without a section, a label marks one card unit with a heading only when it sits in it alone: its wrapper up to the frame holds nothing but the label, so an ad box holding a caption and a slot marks no single card beside it. A section is never a page region (`html`, `body`, `main`) nor holds one, and a card that binds its dominant destination is no section. So an editorial section titled "Partners", a section about advertising headed "Werbung", an ad slot captioned "Anzeige" beside editorial cards, a paid label after the first card of a row, a paid label in the first bare-`div` card of a row (only that card is marked), an empty ad slot captioned "Sponsored" opening a row of cards, a list of cards or a single card, and a paid badge beside an editorial section heading mark nothing. Ad words and class labels never head a section. Other labels never climb: an ad word outside every card (bare `div` layouts, an ad slot beside a teaser in a row) binds nothing, accepting a missed ad over a lost story. Marking is per card: a URL is sponsored (`#sponsored?`) only when every anchor to it sits inside a marked card, so a promo slot never hides the editorial card linking the same story. PageLinks walks lazily: `#sponsored?` walks markers and resolves only the anchors of marked cards, linked-label units and section candidates, then, when any card is marked, the remaining anchors once; placement, canonical and sparse checks resolve every anchor on first use. Cleanup drops sponsored items of every source after dedupe, tallied as `sponsored`: a paid post in the site's own native feed is as sponsored as its card. `auto_source.cleanup.keep_sponsored: true` keeps them; a kept item is titled by its headline alone, since `Html::TitlePieces` never reads a paid phrase (`Sponsorship.paid_text?`) as kicker or headline text (an ad word such as "Werbung" stays a topic kicker). Known gaps (accepted misses): a sponsored strip with no visible label and no class marker (only an element `id` or tracking attribute; ids are not read, since layout ids such as `…-Native-1` also wrap editorial stories), an ad word on a topic chip, and a paid phrase alone in a wrapper that opens a row of editorial cards (read as that row's header).

## Auto-source corpus

Labeled synthetic pages under `spec/fixtures/auto_source/corpus/` (hosts `example.com` only); each page (`.html` or `.json`) has a `.yml` sidecar listing its expected article URLs. `AutoSourceCorpus` (`spec/support/auto_source_corpus.rb`) is the sole runner: fixed base URL, no network, and no request session unless the sidecar names a `responses:` directory (relative to the corpus root) of saved follow-up responses, served by `SavedResponses` (`spec/support/saved_responses.rb`), so a native-feed page can sit in the ratchet. It scores admitted URLs per page as junk (not in the sidecar) and real (in the sidecar); URLs in a sidecar `media:` list (audio or video items a page may admit beside its articles) are neither, and reports whether `SST::Normalizer` ran (observed by a spec-side probe, not a `lib/` hook). `bin/auto-source-corpus` prints the table. `auto_source_corpus_spec.rb` ratchets against `corpus/baseline.yml`: it fails only when a page's junk rises or real-found drops. Re-record intended changes only via `make corpus-baseline`. A sidecar may also carry a `titles:` map (expected URL to exact title); the table's `title_miss` column counts titles the admitted article does not carry verbatim, and the ratchet fails only when that count rises. Likewise an `enclosures:` map and an `images:` map feed the `encl_miss` and `image_miss` columns, ratcheted the same way. An `enclosures:` value is either a hash of the facts of the RSS enclosure the item ships (`FeedBuilder::ItemPresentation.rss_enclosure_for`), any of `url`, `type`, `length` (bytes, 0 when unknown) and `duration` (seconds), where each key present must match and absent keys are not checked, or null, meaning the item must ship no RSS enclosure; an `images:` value is the item image URL, or null for none. A missing item counts as a miss. Adding a page means adding its sidecar and re-recording. Saved pages are UTF-8 by contract: `AutoSourceCorpus.auto_source(path:, url:)` is the one builder of a Response from a saved page file and declares `charset=utf-8`, so a stale in-page `<meta charset>` never decodes the page.

`bin/compare-revisions BASE HEAD --pages DIR [--limit N]` (`make compare-revisions`) compares two git revisions on saved pages kept outside the repo. `DIR` holds the pages plus a `manifest.tsv` of `<file><TAB><base url>` lines (`#` comments allowed); `--limit` keeps the first N entries. Each revision runs in a detached temporary worktree (removed on exit) with its own `lib/` and Gemfile.lock gems; pages (UTF-8 files, like the corpus) run offline through `AutoSourceCorpus.auto_source` (the one runner). The report lists per page item counts, items lost and gained, title changes, Cleanup drop tallies and wall time, then a totals line. Diff and report logic lives in `spec/support/revision_comparison.rb` (`RevisionComparison`), covered by its spec. The tool never writes into the repo.

The synthetic `title_*` and `sponsored_*` pages record the #574 gaps: a spaced-colon kicker, block elements in a heading, clock prefixes, non-English type markers, ad-labelled and `rel="sponsored"` cards, and an advertising story that must be kept. The #576 pages add section, linked and native-container sponsorship labels, it/nl/pl/sv/ja labels, and headline noise placement. Their baseline rows are the failing starting point the title and sponsored phases ratchet down; the `title_*` rows are at 0 title misses since § Article title landed.

## Article title

Owned by `Html2rss::Article::Title`. Whitespace collapse (newlines included, `Title.collapse`) is universal: `Article#initialize` applies it to every title, and it also drops invisible characters (`Title::INVISIBLE`: soft hyphen U+00AD, zero-width space U+200B, word joiner U+2060, byte-order mark U+FEFF; zero-width non-joiner and joiner U+200C/U+200D stay, since they spell Persian, Urdu and Indic words and join emoji sequences), so verbatim publisher and native-feed titles lose them too. Composition (`Title.compose`: `Kicker: Headline`, noise stripping) is opt-in per caller via `Article.new(compose_title: true)`; the default keeps the title verbatim. Opt-in callers: `Html::SstArticleExtractor`, which reads the cards of the heuristic scrapers (`Scraper::HEURISTIC_SCRAPERS`: `SemanticHtml`, `Html`); they yield composed `Article`s. Every scraper that yields Hash items carries a publisher-declared headline, so `AutoSource` builds those collapse-only unless the item carries an explicit `kicker:` (one rule: `compose_title: item.key?(:kicker)`). `JsonState` (and so `XhrArticles`, `JsonDocument`) reads that kicker from the closed field list `ArticleNormalizer::KICKER_KEYS` (`overline`, `kicker`, `kickerText`, `topline`, `dachzeile`, `eyebrow`) beside its headline, only when a headline exists; the headline stays verbatim and `Title` only joins and trims (a kicker already opening the headline is dropped). Schema, Microdata and Microformats2 have no kicker field and never pass one. Otherwise collapse-only: structured in-page data (`Schema`, `Microdata`, `Microformats2`, `JsonState`, `XhrArticles`, `JsonDocument`), publisher endpoints (`NativeFeed`, `WordpressApi`, `Sitemap`, `MetaOembed`), configured `selectors` titles and syndication items (`FeedPipeline`) stay verbatim, so a real headline `10:00 Budget vote` or `Video: ...` survives. (`Scraper::PAGE_SCRAPERS` is the `blank_title` split only.) Scrapers pass `title:` (the headline) and, when the source exposes one, `kicker:`; Article stores only the result (`kicker` is not in `PROVIDED_KEYS`, so it is no selector key, and it is ignored without `compose_title`). Composition collapses whitespace, trims stray separators from both parts (one constant set, `Title::SEPARATOR_MARK`: `: | • · – — - / > » › →`, each a leading separator only when whitespace follows, so a sign `–5 Grad`, a path `/e/` or a German `»quote«` is not one, nor `>` before a number (`> 50 Prozent`); trailing, `: | • · – —` always and `- / > › →` after whitespace, while a trailing `»` closes a French quote and stays), so a headline opening with a separator after the kicker (`Kicker</span> – Headline`) and a kicker ending in one (`Kicker -`) both give exactly `Kicker: Headline`. It normalizes an inline kicker boundary (`Kicker : Headline` → `Kicker: Headline`, only after at most eight words ending in a letter or closing quote/bracket, so `16 : 9` keeps its colon), and drops a kicker that is blank, a type marker, or already opens the headline as a whole word (a headline that only mentions it further in keeps it). When the headline is blank, the kicker alone is the title (Cleanup's title floor then judges it: `MIN_WORDS` = 3 words counted by `Html2rss::WordCount`, the one definition of a word — a letter/digit run, one word per six characters when the run holds Han, Hiragana or Katakana, since such text has no spaces; the same count serves the short-anchor-label rule of link noise and the description richness of entry dedupe; structural scoring — `Scoring::ContainerAssessor`, `SST` density — keeps its own raw run count, because counting CJK chunks there changes which container wins on real pages). Cleanup drops an untitled item from a page-derived scraper (`Scraper::PAGE_SCRAPERS`) as `blank_title`; a publisher-declared item may be untitled (microblog feed posts) and is kept. Headline text is never noise-stripped by text rules: `16:10 laptops…`, `23:21 – Handball…`, `20:15 Uhr: Neuer Krimi…`, `9:41 is…` and `12:00 noon…` stay verbatim, because the string cannot tell a timestamp from headline words. Noise is one closed multilingual (en, de, fr, es, it, nl, pl, sv, ja) vocabulary on `Article::Title`: valid clock times (`CLOCK`, `00:00`–`23:59`, so a score `28:25` is never a clock), Japanese calendar dates (`DATE_PIECE`: `11月12日`, `11月12日 16:42`, optional year), field labels (`Section:`, `Rubrik:`, `Thema:`, `Rubrique :`, `Sezione:`, `Onderwerp:`, `Dział:`, `Ämne:`, `カテゴリー：`, `Article:`, `Artikel:`, `Artículo:`, `記事：`; the colon may be full-width and is required, so a bare `Article` stays text), and type labels with their marker (`Article type: Video`, `Artikeltyp: Video`, `Tipo di articolo: Video`, `記事の種類：動画`). `TYPE_MARKERS` are content formats only (video, audio, gallery, live, press release, full episode; Japanese `速報`, `詳報`, `独自`, `動画`, `写真`, `中継`, `生中継`, `ライブ`, `プレスリリース`), never topics or genres (`Analyse`, `解説` stay kicker text). A Japanese headline opening with a bracket (`【…】` or `＜…＞`, at most thirty characters, headline text after it; `「…」` is a quote, never a label) loses it when its text is a type marker (`【速報】`, `＜動画＞`) and otherwise gives it as the kicker (`【市長外交】視察…` → `市長外交: 視察…`) unless the source already gave a kicker, in which case the headline stays whole; as a kicker the same bracket label is noise. A date chip closing the headline leaves it even when text touches it, via `TitlePieces#date_chip?`: a date-only element (`DATE_PIECE`, `Title.date_piece?`: the chip of a teaser card with no date class) or a date element holding only a clock time (`late <time>22:10</time>`; a clock in a plain element, `at <b>20:15</b>`, stays). It applies to the kicker as text (a leading clock set off by a separator, labels) and to standalone elements. Element rules are owned by `Html::TitlePieces`, the one kicker and headline reader both extractors call (SST and Nokogiri nodes, given the card root, the headline source — heading, else anchor — and the selected anchor), so both give one title for the same markup. It holds the headline rule; `TitlePieces::Kicker` holds the kicker rule; both read nodes only through `TitlePieces::Nodes` (`SstNodes`, `NokogiriNodes`: the per-kind reads, and the shared element facts — class words, concealed, date and noise elements — each read once per card node), so no rule branches on node kind. All its rules read elements, never headline wording. **Headline:** a `data-title` attribute on the heading or anchor wins. A heading or anchor made only of element pieces (no word in its own direct text) is read from its headline piece: its one outermost headline-marked descendant (`HEADLINE_WORDS` class words `title`, `headline`, `h1`–`h6`; never `subtitle`/`sub-title`/`subTitle` or a label-marked element, `LABEL_WORDS` below), else the selected anchor when it is the only link inside the heading (a headline split over several links stays whole). Pieces beside the headline piece (tags, dates, lead paragraphs, footers) are no part of the title. **Left out of headline text:** the kicker; concealed elements (`Html::Visibility.concealed?`, § Visibility) unless they hold the only words (the accessible name of an otherwise empty link); date, time and duration elements (`time`, or a class word in `DATE_WORDS`: `date`, `time`, `duration`, `timestamp`, `datetime`; class tokens split on `-`, `_` and camelCase, so `update` or `candidates` never match) wherever they sit, unless they sit in running text (direct text holding a word right before or right after them: `resume on <time>Friday</time>` and `moved to <time>Friday</time> after` stay, while a date set apart in its own element or across blank text is a chip and leaves) — this revises #575, which removed them only before the first word; lead pieces (`LEAD_WORDS`: `lead`, `leadin`, `summary`, `excerpt`, `standfirst`, `dek`, `abstract`) while words remain; tag pieces (`TAG_WORDS`: `tag`, `tags`, `subtitle`) that close the text while words remain; and an element whose text is only a clock or only a label (`Title.headline_noise_piece?`) before the first word (`leaves at <strong>20:15</strong> from…` and `<em>Category:</em>` mid-sentence stay). **Kicker**, first match: (1) a kicker-marked element (`TitlePieces::KICKER_WORDS` class words incl. `topline`, `data-tb-kicker`), one inside the heading or anchor preferred over one beside it; (2) a label leaf (`LABEL_WORDS`: `kicker`, `eyebrow`, `overline`, `pretitle`, `topline`, `prefix`, `label`, `alert(e)`, `live`, `region` + `name`) that opens the heading or anchor text (after concealed and date elements) with headline words after it; (3) the nearest worded piece right before the headline piece (walking up to the heading or anchor; direct text with a word in between stops it), descending into the last worded child of an element-only box, when it is no paragraph, no lead piece and holds no media. Each kicker piece is judged with `Title.noise_piece?` (blank, clock, closed field label, type marker; any other piece ending in `:` is kicker text, so `<strong>Conflict:</strong>` gives `Conflict: Headline`), and date, time and concealed pieces are dropped from it; a kicker that already opens the headline is not repeated (`Title.compose`). `ArticleRules::Description` reuses `CLOCK_PIECE` (`Title.clock_piece?`, chip peeling) and `TYPE_MARKERS` (referenced directly) and keeps only description-specific sets (CTA, listing section names, date shapes). Kicker marks (`TitlePieces::KICKER_WORDS` class words, `data-tb-kicker`) have one owner. A marked kicker node is the outermost kicker-marked element that carries kicker text, stands beside the headline, and holds no word outside its noise and its kicker-marked parts. It carries kicker text when it is no noise element itself and holds a letter or digit outside its noise pieces, so an icon, clock or `time` leaf is skipped. It stands beside the headline unless it is or wraps the heading (or, without a heading, the anchor), or holds all of the heading's text. So `kicker__topic` + `kicker__sub` in a `kicker` give one kicker (`Politik Bund`), an `eyebrow-row` holding a status beside its `eyebrow` gives the eyebrow, and `kicker-group`, `headline__inner--has-kicker` and a `teaser--with-kicker` card are wrappers or modifiers, never the kicker. A kicker nested in the heading or anchor is excluded from the headline text and passed as the kicker. `Html::ArticleExtractor` is itself an opt-in caller: it returns `Article::Title.compose(headline, kicker:)` as its `title` because Selectors' enhance merges hash keys one by one and cannot tell an extracted title from a selected one; a separate `kicker` key would prefix an explicitly selected title, while the pre-composed title only ever fills an empty one and reaches `Article` verbatim. Composition is idempotent, so `with_url` and Marshal round-trips keep the title. Corpus pages `title_kicker_selection`, `title_headline_noise_placement`, `title_separators_typography`, `title_heading_kicker_leaves`, `title_date_elements_anywhere`, `title_teaser_lead_card`, `title_hidden_text`, `title_offscreen_twin_anchor`, `title_inline_word_spacing` and `title_invisible_characters`, `title_localized_labels_more`, `title_japanese_bracket_labels` and `title_unspaced_cjk_floor` pin these rules; no known gap stays out of their `titles:` maps.

## JSON state article node

Which hashes of a JSON state entry hold its article fields. Owned by `JsonState::ArticleNormalizer.article_sources` (detector and normaliser both consult it; `ValueFinder` reads only the keys of the hashes it is given). ## Media enclosures

Media-file facts (URL, MIME type, byte length, playback duration in seconds) are owned by `Html2rss::Article::Enclosure`, with its kind predicates (`audio?`, `video?`, `media?` for either, `image?`, `page?` for a web page (`Enclosure::PAGE_TYPES`: `text/html`, XHTML and the server-page types guessed from script extensions such as `.php`, `.asp`, `.aspx`, `.jsp`, `.cgi`, `.cfm`; other `text/*` files such as `.txt`, `.csv`, `.ics`, `.vtt` are downloads), all case-insensitive and ignoring MIME parameters, `player_page?` for a watch or player page declared as a file: a web page, or an untyped `application/octet-stream` URL with no file extension (`file_extension?`) and no declared byte length, since only a file has one, `document?` for a downloadable document or archive: no media file, image, stream playlist or Flash player (`Enclosure::STREAM_TYPES`: `application/vnd.apple.mpegurl`, `application/x-mpegurl`, `application/dash+xml`, `application/x-shockwave-flash`) and no player page) and the parsers extractors call: `Enclosure.parse_size` (a declared size such as Schema.org `contentSize`: `12345`, `850 KB`, `12.3 MB`, `1 MiB` to bytes; SI units count in thousands, binary units in 1024s) and `Enclosure.parse_duration` (ISO 8601 `PT1H2M3S`, `PT45M`, `P1DT1S`, or a clock `1:02:03`, `45:00`, `2700` as `itunes:duration` and Media RSS write it, to seconds); both return nil for anything unparseable or not positive. An enclosure may carry a `kind` (`:audio` or `:video`) when its source proves what the file is (an HTML player, a Schema.org media object): a file with no declared type whose URL names no media type (no or an unknown extension, or a server page) is then typed `Enclosure::KIND_TYPES` (`audio/mpeg`, `video/mp4`, the most widely played formats, since an RSS enclosure needs a concrete type), while a declared type or a known extension (an `.m3u8` playlist, a `.webm` file) still wins. An unknown byte length is 0 and an unknown duration nil; html2rss never probes a file for either. `FeedBuilder::ItemPresentation` owns the choice and the feed kind: an item's RSS `enclosure` is its first audio or video file in document order, else its first downloadable document or archive (`Enclosure#document?`: PDF, ZIP); images, stream playlists, Flash players and watch or player pages are never one. A feed is a media feed (`ItemPresentation.media_feed?`) when more than half of its items carry an audio or video enclosure (exactly half is not). Only then does `FeedBuilder::Rss` add the podcast tags clients play from: channel `itunes:image` (channel image) and `itunes:author` (channel author), item `itunes:duration` (`HH:MM:SS`, plain seconds from 100 hours on) and `itunes:image` (item image), each only when known; never `itunes:explicit` or a category, since the target is playback, not directory submission. (The `rss` library declares `xmlns:itunes` on every RSS 2.0 document, so the declaration itself is not a media-feed signal.) JSON Feed lists every enclosure as an attachment, with `size_in_bytes` only when positive and `duration_in_seconds` when known. The item description renders each enclosure by those same predicates (`Html::Rendering::MediaRenderer`: image, video, audio, then PDF), never by its own type patterns. Selector configs get this through the shared builder; there is no selector key for it. Native feed items carry the media their feed declares (`Syndication::ItemMedia`, called by `Syndication::Parser`): RSS 2.0 `enclosure` (`url`, `type`, `length`), Atom `link rel="enclosure"` (`href`, `type`, `length`) and Media RSS `media:content`, also inside `media:group` (`url`, `type`, `fileSize`, `duration`), in document order and once per URL; an item `itunes:duration` is the duration of every audio or video file that declares none (never of an image or document). It matches item elements by namespace, as the `rss` library reads them: RSS 2.0 `item` (no namespace) under `rss/channel`, RSS 1.0 `item` under `rdf:RDF`, Atom `entry` under `feed`; when their number differs from the parsed items, it logs `syndication.item_media_mismatch` with the feed URL and reads no media. A document containing none of `<enclosure`, `rel="enclosure"` (either quote) and the Media RSS or iTunes namespace is not parsed a second time. A Media RSS `medium` is a kind hint, never a drop signal: `medium="audio"` or `medium="video"` is the file's kind, so an untyped file (no declared type, no known extension) is `audio/mpeg` or `video/mp4` (`Enclosure::KIND_TYPES`, the one kind table HTML players and Schema.org media objects use too), and `medium="image"` keeps an untyped file an image. The reader drops every watch or player page (`Enclosure#player_page?`) not declared an image, so it is neither an RSS enclosure nor a JSON Feed attachment: `medium="video"` on `/watch/42` drops, `medium="audio"` with a `fileSize` on `/files/42` ships as audio. The item image is its `itunes:image` (`href`, or the URL written as the element text), else its first `media:thumbnail`, else its first image file among its media (`medium="image"` or an image type, declared or guessed from the URL) (Article `image`); that file stays an enclosure (a JSON Feed attachment, never the RSS one). Publisher-declared durations are kept as given, with no cap. Corpus pages `t4_podcast_feed_enclosures` and `t6_news_feed_image_media` pin the feed reader. An Atom entry's URL is its `rel="alternate"` link or a link without `rel`, never an enclosure, `self` or other link; an entry with neither is skipped like any item without a URL. When a page card repeats a feed episode, the feed item's enclosures win (Cleanup merge: the first copy keeps every field it carries).

Which HTML elements become enclosures is one rule, `Html::ArticleRules::Enclosure.from_element`, that both card extractors (`Html::SstArticleExtractor` and `Html::ArticleExtractor::EnclosureExtractor`, the Nokogiri path of selectors `enhance`) only adapt their node API to, then pass through `ArticleRules::Enclosure.unique` (one enclosure per URL at its first position, a duplicate declaring a type winning, as in `<video src=x><source src=x type=video/webm>`): `img[src]` (not inline `data:`), `audio[src]` and `video[src]`, a `source[src]` with its `type` inside an `audio` or `video` player (the nearest player ancestor, since the HTML4 parser nests sibling `source` elements; a `picture` source is none), each carrying its player as the kind, and file links (`ArticleRules::Enclosure.file_link?`) whose URL path ends in `.pdf`, `.zip`, `.tar.gz`, `.tgz` or an audio or video extension of `Enclosure::MEDIA_TYPES` (any case, query and fragment ignored; typed from the extension, so a tarball is `application/gzip` and an episode's `Download` link `ep.MP3?src=list` is `audio/mpeg`), with or without a `download` attribute. Links are read only inside the item's card (the segment root on the SST path, the selected item on the Nokogiri path), never from the page around it, so a livestream link in the site navigation attaches to no card. A file link inside a `<noscript>` counts: the Nokogiri HTML parser reads `noscript` content as markup, and `SST::Normalizer` keeps a `noscript` only as the file links inside it (its text stays invisible, and it is chrome anywhere through `Tags.chrome_scope`, so those links never compete as a card's primary link or a content anchor; one XPath over each `noscript` element, and none is kept on a page without such a link). A download link and a player naming the same file ship it once, at the first of the two in document order, with the player's declared type when it has one (`unique`); otherwise players and links take their document order, so a link before a different player's file is the item's RSS enclosure. A card whose headline links the file itself keeps that file as its item URL (no article-URL rule rejects file paths) and also ships it as its enclosure. Only an http(s) URL is an enclosure: `data:`, `blob:`, `javascript:` and `mailto:` references are none. An `iframe` is never an enclosure, and html2rss never fetches an embed player page, so a card with only an embedded player stays an item without one. A `<video poster>` is the item image only when the card has no other image (srcset, `img`, CSS background), through the image owners (`ArticleRules::Image.remote_src?`, `SstArticleExtractor#extract_image`, `ArticleExtractor::ImageExtractor`), never an enclosure. A URL with no declared type is typed by `Article::Enclosure.guess_content_type_from_url`: a media extension maps to its playable type (`Enclosure::MEDIA_TYPES`: `.mp4`/`.m4v` `video/mp4`, `.webm` `video/webm`, `.ogv` `video/ogg`, `.m4a` `audio/mp4`, `.mp3` `audio/mpeg`, `.ogg`/`.oga` `audio/ogg`, `.opus`, `.aac`, `.wav`, `.flac`), since MIME::Types lists those under several types and puts a non-playable one first (`.mp4` as `application/mp4`); any other extension takes the first MIME::Types match. An HLS playlist (`.m3u8`, `application/vnd.apple.mpegurl`) is no media file: it never makes a media feed. Corpus pages `media_audio_cards`, `media_video_cards` and `media_download_link_cards` pin these rules.

Schema.org media in structured data is read by `AutoSource::Scraper::Schema::Thing` (JSON-LD; Microdata article roots pass their nested `video`, `audio` and `associatedMedia` through the same reader, while a Microdata media root is no item). A `VideoObject`, `AudioObject`, `PodcastEpisode` or `Clip` is an item wherever it appears (standalone, in `@graph`, in an array, or as an ItemList element) and carries `media: true` (`Thing::MEDIA_TYPES`; `Thing::ITEM_TYPES` adds the article types); a media object nested in an article stays part of that article. Enclosures come from the `contentUrl` of the nested `video`, `audio` and `associatedMedia` objects (object or array, in that order; `@id` stubs resolve against the same document) and of the media item itself; an `ImageObject` is never one (images are the item image). Each takes its MIME type from `encodingFormat`: a MIME type (`audio/mpeg`, lowercased, parameters dropped), or a media format name (`mp3`, `.m4a`, `webm`) mapped through `Enclosure::MEDIA_TYPES`; any other name is ignored and the file name decides. The object's `@type` gives the file's kind (`Thing::MEDIA_KINDS`: `AudioObject` and `PodcastEpisode` audio, `VideoObject` and `Clip` video), so an untyped extensionless `contentUrl` is still played; only an http(s) `contentUrl` counts. `contentSize` becomes the byte length (`Enclosure.parse_size`) and `duration` the seconds (`Enclosure.parse_duration`), the media object's own, else the item's (a `PodcastEpisode` usually states it on the episode, its file in `associatedMedia`). `embedUrl` is a player page: never an enclosure, and the item link only as the last resort after `url`, `mainEntityOfPage` and an absolute `@id`. `contentUrl` is never the item link, so a media object with only a file and no page yields no item. A player-only object (no `contentUrl`) is an item without enclosure. Nothing is fetched.

## Pagination strategy registry

Supported pagination strategy names and factory classes live in `RequestSession::Pager::STRATEGIES` / `Pager.strategy_names`. Selectors validation (`Selectors::Config::Items`) and the exported JSON schema enum consume that list. Runtime pagination uses `Pager.for` (e.g. `rel_next` → `Pager::RelNext`).

## Extractor / post-processor registry

Module guide: `lib/html2rss/selectors/README.md`.

Extractor and post-processor names live in `Selectors::Extractors::NAME_TO_CLASS` and `Selectors::PostProcessors::NAME_TO_CLASS`. Each strategy owns config-facing options as an `OPTIONS` Array of `Selectors::OptionSpec` (name, type, required). `Config::SelectorsValidator::Selector`, `Selectors::OptionSpec.for` / `expectation_for`, and `Selectors::SchemaExport` consume that contract; post-processor `Base` enforces `OPTIONS` plus optional `VALUE_TYPE` at runtime. Extractors run as `new(xml, **config)`.
